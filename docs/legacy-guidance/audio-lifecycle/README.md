# Audio Editor optional lifecycle research

Based on d731fe392; no deployment. The lifecycle tracks unsaved edits and reports pending file operations, single- and MultiTrack recording, microphone requests/streams, asynchronous effects, imports, project saves and mixdowns. A session lease prevents input and new host actions, pauses playing audio and resumes it if the lease is released. Active capture or processing refuses the lease; it is never stopped merely to sign out. Disposal closes the lifecycle once and keeps the existing stream, worker and frame cleanup.

Run `node --test tests/audio-lifecycle-reference.test.mjs`. Build an isolated audio-editor catalog, run `tests/jsketcher-preview-csp.py --isolated` against it and start a dedicated Chromium with fake media input and fake media permission. Run `tests/audio-lifecycle-session-review.test.mjs` using the loopback CODI_TEST_URL and CODI_TEST_CDP. The isolated signed-account test exercises a real generated tone and effect, change during confirmation, held WAV save and matching server copy, two independent windows, a live fake microphone, failure/release with playback resumption, closing one window with live capture, account isolation and repeated disposal. These are desktop Chromium tests; physical microphone hardware, recording a complete clip, actual MultiTrack playback/recording and phone layouts remain unqualified. Playback resumption is subject to browser audio policy. No production data or public services were used.
